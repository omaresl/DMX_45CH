# WS2811 LED driver chain

3-channel constant-current LED driver (SOP8, Worldsemi), used here as
MOSFET gate drivers: 15 chips in cascade (U29–U43) drive the 45 DC channels
through AO3400 MOSFETs. Source: `Doc/Components/WS2811.pdf` (V2.2).

## How the firmware drives it

- **SPI1 @ 3 Mbps bit-bang**: each data bit is one SPI byte —
  `0xFC` (6/8 high ≈ 2.0 µs) = WS2811 `1`, `0xC0` (2/8 high ≈ 0.67 µs) = `0`.
- **Frame**: 15 chips × 24 bits = 360 bytes (`WS2811_CH`), order **RGB,
  MSB first**, followed by 160 zero bytes (`WS2811_BREAK`) = ~427 µs low
  as reset code (≥ 280 µs required by this revision ✓).
- **DMA circular** (`SPI1+DMA1_Ch3`): the frame repeats every ~1.38 ms with
  no CPU load. No double buffering — `ConvertDMXData` rewrites the buffer
  while DMA transmits (tearing possible, accepted).
- Channel mapping: `DMX_Channels[9..53]` → 45 channels = 15 RGB pixels;
  channels 0..7 are AC lamps (not on this chain), index 8 unused.
- Pin 7 (`SET`) is **NC** on this revision — no speed-mode strapping needed.

## Encoding pulses (SPI 3 MHz, bit = 333 ns)

| Pattern | Meaning today | High pulse | Low pulse | V2.2 window | Status |
|---|---|---|---|---|---|
| `0xFC` | `1` (`TRUE_DATA`) | 2.0 µs | 0.67 µs | `T1H` 580 ns–1 µs | out of spec (H ×2) |
| `0xC0` | `0` (`FALSE_DATA`) | 0.67 µs | 2.0 µs | `T0H` 220–380 ns | out of spec (H in `1` zone) |
| `0xC0` | candidate `1` | 667 ns | 2.0 µs | `T1H` 580 ns–1 µs | in spec |
| `0x80` | candidate `0` | 333 ns | 2.33 µs | `T0H` 220–380 ns | in spec |

Long lows (2–2.3 µs) are harmless: reset needs 280 µs, rate stays at
375 kbps under `FMAX` 600 kbps. Current encoding works on HW by NZR
decoder tolerance (shipped 0.2/0.3); the candidate swap is reserved for
field validation, not applied.

## Encoding margin note

Nominal V2.2 windows are `T0H` 220–380 ns / `T1H` 580 ns–1 µs, while the
SPI encoding produces ~2.0 µs / ~0.67 µs high pulses — outside the nominal
windows on paper. In practice the NZR decoder tolerates it, and this exact
encoding is validated on HW (shipped through OfficialRelease 0.2/0.3).
If a new WS2811 batch ever misbehaves, revisit SPI rate/encoding first.

## Device facts (V2.2)

| Symbol | Meaning | Value |
|---|---|---|
| `T0H / T0L` | `0` code high/low | 220–380 ns / 580 ns–1 µs |
| `T1H / T1L` | `1` code high/low | 580 ns–1 µs / 580 ns–1 µs |
| Reset | low time | ≥ 280 µs |
| `FMAX` | data rate | 600 kbps min @50% duty |
| `VDD` | supply | 3.5–5.7 V (`VCC_WS` rail) |
| `VIH / VIL` | `DIN` thresholds | 0.55×VDD / 0.3×VDD |
| `IOL` | OUTx constant current | 14–18 mA (drives MOSFET gates here) |
| `VOUT` / `DIN` | withstand | 20 V / 9.5 V (24 V momentary short safe) |
| Cascade | @30 fps | ≥ 1024 points (15 used) |

First chip takes the first 24 bits, reshapes and forwards the rest down
`DO`→`DIN`; outputs update on the reset code. To verify on HW: `SET` pin
strapping (low-speed) and `VCC_WS` level.
